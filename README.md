# BLDC Hall-Sensor Fault Detection

Hall-sensor displacement fault detection for BLDC motors from phase-current data, plus a
single-current start-up block. Built on the reference implementation
[yklee1014/BLDC-Fault-Detection](https://github.com/yklee1014/BLDC-Fault-Detection) and the
[IEEE DataPort BLDC-HSD dataset](https://ieeexplore.ieee.org/document/10707261).
Reference paper: Hong & Lee, *IEEE Access* 12 (2024), included in this repo.

> **Data provenance.** The paper states its dataset was generated by MATLAB simulation validated
> against experiments. In all 10 raw recordings used here ia+ib+ic = 0.000, which is consistent with
> simulated data. Treat results as "on the published dataset", not as proof on a physical motor.
> Every recording is only 300 ms long, and there is a single `no_delay` recording.

## 1. Original 8-CNN run (optimistically biased)
MobileNetV1 averaged 74.3% (72.9 / 79.2 / 70.8 % at 0.0001 / 0.005 / 0.01 s).

**Known flaw:** `BLDC_Hall_Detection_full.py` passes `validation_data=(X_test, y_test)` with
`EarlyStopping(monitor='val_accuracy', restore_best_weights=True)`, so the best epoch was chosen using
the test images (about 48 of them). These numbers are therefore biased upward and the model ranking
(MobileNetV1 best) is not reliable. All models were also fed MobileNet-style input scaling.

## 3. Raw-current detection (`BLDC_raw_current_classifier.py`)
40 ms steady-state windows (first 150 ms skipped), 23 features, LogReg / SVM / RandomForest, no
test-set tuning. Balanced accuracy: A = time-split, B = train on other fault files and test on a held-out one.

| Level | A (all 3 models) | B: unseen file |
|---|---|---|
| 0.0001 s | 100% | SVM 100, RF 100, LogReg 79.2 |
| 0.005 s | 100% | SVM 100, RF 100, LogReg 83.3 |
| 0.01 s | 100% | SVM 100, RF 100, LogReg 83.3 |

**Do not over-read these.** Each recording gives only 12 overlapping windows (about 3 to 4 independent
stretches); the single normal recording has about 4 test windows. Recording identity cannot be excluded
from the classifier scores alone. The feature table (`BLDC_feature_table.py`) is the stronger evidence:

| Level (files) | recon_b | corr_lag_b | corr_lag_c | h3/h1 |
|---|---|---|---|---|
| no_delay (1) | 0.056 | 0.998 | 0.999 | 0.005 |
| 0.0001 s (3) | 0.236 | 0.972 | 0.972 | 0.051 |
| 0.005 s (3) | 0.800 | 0.743 | 0.742 | 0.335 |
| 0.01 s (3) | 3.275* | 0.291 | 0.289 | 0.740 |

`corr_lag_*` is the correlation between a phase and ia delayed by T/3 or 2T/3. Its per-file values do
not overlap between severity levels, and the three files of each level agree.
\*At 0.01 s one phase carries almost no current in each file (rms ratio 0.13 or above 7), which inflates
ratio-based features. Prefer the correlation features for that level.

## 4. Single-current start-up block
Goal: measure only ia and generate ib and ic.

* `single_current_startup.py`: sine-tracking (SOGI) generator. Works on a simulated 5 to 140 Hz ramp
  (within 15% error from about 80 ms, about 6% at speed) but **fails on the dataset recording**: the first
  ~10 ms of ia is a one-sided surge (mean 45.7 A, min 0.00 A), not an oscillation.
* `single_current_startup_2stage.py`: two-stage block. Stage 1 (no valid oscillation yet) outputs nothing;
  Stage 2 turns on once two consecutive periods of ia agree within 15%, then ib = ia delayed by T/3
  and ic = ia delayed by 2T/3 (causal, past samples of ia only). Chosen because the six-step currents are
  quasi-square shifted copies, not sinusoids.
* Results on the dataset (`single_current_startup_2stage_all.py`):

| Recording | Stage 2 on (ms) | ib error | ic error |
|---|---|---|---|
| no_delay | 59.2 | 6.6% | 5.5% |
| 0.0001 s | 59.6 | 17.7% | 26.5% |
| 0.005 s | 54.7 | 51% | 76% |
| 0.01 s | 40.7 | 114% | 740% |

  Error = RMSE / steady amplitude, only where Stage 2 is on. The block works for a healthy motor and degrades
  as the Hall sensor is displaced, because ib and ic stop being clean 120-degree copies of ia.
  There is no ib/ic output for the first ~59 ms. The fault-file rows use one file per level, with different
  phases displaced, so they are not like-for-like.

## Limitations
* Recordings are 300 ms each; one normal recording only.
* Sections 2 and 3 are single-dataset results; section 3 needs more normal recordings to rule out
  recording identity.
* Section 2 caches backbone features and uses no on-the-fly augmentation (differs from section 1).

## Setup
```
py -3.12 -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install tensorflow scikit-learn numpy pandas pillow openpyxl matplotlib
```
Dataset is not included; download it from IEEE DataPort and edit the path constants at the top of the scripts.

## Usage

    python BLDC_Hall_Detection_full.py            # original 8-CNN run (section 1)
    python BLDC_new_methods.py --quick            # quick check; drop --quick for the full 13-model run (section 2)
    python BLDC_raw_current_classifier.py         # raw-current classifier (section 3); reads Excel once, then cached
    python BLDC_feature_table.py                  # per-recording feature table (section 3)
    python single_current_startup_2stage_all.py   # start-up block on all recordings (section 4)

Edit the data path constants at the top of each script first.
